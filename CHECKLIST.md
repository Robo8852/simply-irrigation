# Simply Irrigation LLC — Website Launch Checklist

## 🏗️ CORE PAGES & CONTENT

- [ ] **Homepage** with clear value proposition (who Fernando is, what areas he serves, what he does, hero image with CTA)
- [ ] **About page** — Fernando's bio, story, years of experience, professional photo, personality, why customers should choose him
- [ ] **Services page** (pillar page) — overview of all services with links to individual service pages
  - [ ] **Irrigation Installation** detail page (description, process, benefits, photos, CTA)
  - [ ] **Irrigation Repair** detail page (common issues, fast response time, emergency info, CTA)
  - [ ] **Irrigation Maintenance** detail page (seasonal maintenance, winterization, benefits, CTA)
  - [ ] **Landscaping** detail page (services offered, portfolio, CTA)
  - [ ] **Tree Removal** detail page (safety info, process, photos, CTA)
- [ ] **Service Area page** — specific cities and neighborhoods served (Bradenton, Sarasota, Lakewood Ranch, Palmetto, etc.) with location-specific content for SEO
- [ ] **Contact page** with form, phone number, email, hours, and embedded Google Map
- [ ] **Testimonials/Reviews section** — display Google reviews, HomeAdvisor reviews, customer quotes (social proof is critical)
- [ ] **FAQ page** — answer common irrigation questions (this is huge for AI overviews and "near me" searches)
- [ ] **Promotional offer page** — "Free Estimate" or seasonal promotion landing page
- [ ] **Blog/Resource section** — educational content (seasonal tips, winterization guides, water conservation, common problems)

## 🔍 SEO & DISCOVERABILITY (Traditional + Generative)

### On-Page SEO
- [ ] Unique, compelling title tags on every page with local keywords (e.g., "Irrigation Repair Bradenton FL | Same-Day Service | Simply Irrigation")
- [ ] Meta descriptions written for every page (160 characters, action-oriented)
- [ ] H1, H2, H3 header tags structured properly with keywords (one H1 per page)
- [ ] Image alt text on ALL images (descriptive, not keyword-stuffed)
- [ ] Internal linking between pages (service pages link to related services and homepage)
- [ ] Clean URL structure (e.g., /irrigation-repair-bradenton not /page?id=123)
- [ ] Answer-first content format (AI engines extract direct answers — put key info first)
- [ ] Conversational language throughout (write how real people search: "We fix broken sprinkler heads same-day" not "Sprinkler head repair services")

### Schema Markup / Structured Data
- [ ] LocalBusiness schema markup (name, address, phone, hours, service area)
- [ ] Service schema markup (for each service page)
- [ ] WebPage schema markup
- [ ] Article schema markup (for blog posts)
- [ ] FAQ schema markup (for FAQ page — AI overviews pull this)
- [ ] AggregateRating schema (if displaying review averages)
- [ ] Organization schema (company info in footer/header)

### GEO (Generative Engine Optimization) — AI Discoverability
- [ ] **Content structured for AI extraction** — clear question-answer format, short paragraphs, bulleted lists
- [ ] **Topical authority structure** — pillar page (main services page) linking to cluster pages (individual services)
- [ ] **Citation-worthy content** — include stats, specific numbers, expert credentials (improves AI visibility 30-40%)
- [ ] **FAQ sections on every service page** — AI overviews love pulling Q&A directly
- [ ] **Brand mentions across the web** — consistent mentions on directories, social media, local news, community sites
- [ ] **Freshness signals** — regular blog posts, seasonal updates, recently updated pages (AI engines favor active sites)
- [ ] **Local conversational keywords** — target "near me" queries and location-specific terms naturally
- [ ] **Review volume and recency** — maintain steady flow of new customer reviews (trust signal for AI)
- [ ] **Track AI overview appearances** — use Google Search Console + SEMRush/Ahrefs to monitor AI citations

### Sitemap & Robots
- [ ] XML sitemap generated and submitted to Google Search Console
- [ ] robots.txt configured properly
- [ ] Sitemap includes all important pages
- [ ] robots.txt doesn't block important content

### Open Graph & Social Sharing
- [ ] Open Graph tags on all pages (og:title, og:description, og:image, og:url)
- [ ] Twitter/X card tags
- [ ] Images optimized for social preview (1200x630px minimum)

## ♿ ACCESSIBILITY (ADA Compliance)

- [ ] Semantic HTML (proper heading hierarchy, `<nav>`, `<main>`, `<footer>`, `<article>`, etc.)
- [ ] Form labels properly associated with inputs
- [ ] Alt text on all images (descriptive and meaningful)
- [ ] All interactive elements keyboard navigable (Tab, Enter, Escape)
- [ ] Focus indicators visible on all interactive elements
- [ ] Sufficient color contrast (WCAG AA minimum — 4.5:1 for text)
- [ ] No color used as the only means of conveying information
- [ ] ARIA labels where needed (especially for buttons without visible text)
- [ ] Videos/media have captions or transcripts
- [ ] Skip navigation links (allow jumping to main content)
- [ ] Mobile-friendly and touch-friendly (tap targets at least 48x48px)
- [ ] Screen reader tested (with NVDA or JAWS)
- [ ] Page zoom works properly (up to 200%)

**Note:** Over 4,000 ADA website lawsuits filed in 2024 — service businesses are targeted. This matters.

## TECH STACK RECOMMENDATION FOR ANTIGRAVITY

Since you're building with Antigravity (Gemini Pro 3) and deploying on Vercel:

- **Framework:** Next.js (Static Export or SSG) — best for local SEO, fast, Vercel-native
  - Alternative: Astro (even faster, simpler)
- **Styling:** Tailwind CSS (already works well with both frameworks)
- **Forms:** Vercel Web Forms or SendGrid for contact form backend
- **Image Optimization:** Next.js Image component or Astro Image
- **Blog:** Markdown-based (MDX) — easy to manage, great for SEO
- **Deployment:** Vercel (automatic builds, fast CDN, serverless functions for forms)
- **Analytics:** Google Analytics 4 + Google Search Console
- **Schema Markup:** JSON-LD embedded in pages (can be generated via frontmatter)

This stack ensures:
- Fast performance (Core Web Vitals green)
- Easy SEO implementation
- Static site (no databases needed for local business)
- Scalable (can add features later)
- GEO-friendly (clean structure, semantic HTML, schema markup built-in)
